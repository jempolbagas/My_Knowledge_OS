# 🧠 Knowledge OS — Obsidian Vault & Automation Hub

Welcome to **Knowledge OS**, a semi-automated Personal Knowledge Management (PKM) vault built on Obsidian. It is designed to bridge active academic studies, teaching curriculum development, and lifelong, curiosity-driven research—all supported by a Python-based background automation system and interactive LLM AI agents.

---

## 🗂️ Vault Structure

The directory structure is strictly organized to separate deadline-driven spaces from timeless concepts and source materials:

```text
10_Knowledge_OS/
├── 00 Inbox/                      # Landing zone for raw, unprocessed notes
├── 10 Spaces/                     # Deadline-bound, structured workspaces
│   ├── 11 College/                # Coursework, lectures, and semester dashboards
│   └── 12 Teaching/               # Curricular materials, worksheets, and lesson plans
├── 20 Brain Atlas/                # Timeless, curiosity-driven knowledge (never archived)
│   ├── 00 Atlas/                  # Indexes, maps of content, and dashboards
│   ├── 10 Library/                # Summaries of external sources and generated explainers
│   │   ├── Papers/                # Academic paper summaries
│   │   ├── Repos/                 # Git repository reviews and notes
│   │   ├── Articles Talks/        # Online articles, videos, and presentations
│   │   ├── Books/                 # Book summaries
│   │   └── Generated Readings/    # Deep-dives generated by AI agents (organized by subject)
│   ├── 20 Concepts/               # Atomic, timeless, one-idea-per-note concept files
│   └── 30 Reference Lib/          # Dense reference materials, cheatsheets, and lecture logs
├── 90 Archive/                    # Completed courses, past semesters, and legacy projects
├── 99 Configs/                    # Templates, queries, and system configurations
│   ├── Templates/                 # Obsidian templates (Concepts, Lectures, Sources)
│   ├── Depth Standard.md          # Content quality bar for agent-generated notes
│   ├── Dataview_Queries.md        # Reference queries for Obsidian dashboards
│   └── Automation_Reference.md    # Script details and SQLite database schema
├── .agents/                       # Project-scoped agent skills and configurations
├── .automation/                   # Hidden automation scripts and relational database
└── GEMINI.md                      # Detailed behavioral guidelines for AI agents
```

## 🏷️ Note Categorization & Filing Rules

To maintain high searchability and clean connections, notes follow strict classification rules:

### 1. Spaces vs. Brain Atlas
* **Spaces (`10 Spaces/`):** If a note is tied to a specific class, teaching task, or competition deadline, it lives here. When a semester or course finishes, its folder is relocated to `90 Archive/`.
* **Brain Atlas (`20 Brain Atlas/`):** If a note is for self-study, research, or curiosity-driven learning with no deadline, it lives here. Files here are never archived.

### 2. Brain Atlas Note Types
Notes in the Brain Atlas are classified into four distinct types:
1. **Library Note (`10 Library/<Category>/`):** Synthesized summaries of external articles, repos, papers, or books. Must contain a `source_url` and use the `Library Source Note` template.
2. **Generated Reading (`10 Library/Generated Readings/<Subject>/`):** Comprehensive, AI-generated explainers that synthesize a topic without a single external source. Must meet the [Depth Standard](file:///mnt/data/life-hub/10_Knowledge_OS/99 Configs/Depth Standard.md) and use the `Generated_Reading` template.
3. **Concept Note (`20 Concepts/<Subject>/`):** Atomic, timeless notes covering exactly *one* idea. Promoted from Library Notes or Generated Readings. Uses the `Concept Note` template.
4. **Reference Note (`30 Reference Lib/`):** Dense raw reference data (e.g., subnetting tables, cheat sheets, log files) that are too unstructured to be atomic concepts.

## ⚙️ Background Automation Engine

The vault runs a background automation suite located in the `.automation/` directory, managed via a systemd user service (`knowledge-os-watcher.service`). It listens for filesystem changes via `inotifywait` and runs a series of Python scripts after a 5-second quiet period:

| Script | Role | Output File |
| :--- | :--- | :--- |
| `build_index.py` | Traverses the vault and compiles a relational node-edge map | `.automation/db/vault_index.db` |
| `linter.py` | Detects broken wikilinks, orphan notes, and missing metadata | `.automation/reports/linter_report.{json,md}` |
| `staleness_checker.py` | Compares Concept source hashes to find outdated notes | `.automation/reports/stale_concepts.{json,md}` |
| `generate_summary.py` | Aggregates vault statistics into a token-efficient JSON | `.automation/reports/vault_summary.json` |
| `git_sync.sh` | Automated background backups (`vault backup: <timestamp>`) | Remote Git Repository |

### The MD5 Snapshot Protocol
To prevent notes from drifting out of date, Concept notes linked to markdown/text sources store a hash of the source file in their frontmatter (`source_hash: "<hash>"`). The `staleness_checker.py` computes a fresh MD5 of the source file and compares it to the stored hash, flagging outdated concepts for revision.

## 🤖 AI Agent Integration

This vault is optimized for collaborative pair-programming and study with AI agents (like Google Antigravity). When interacting with an agent:
* **LLM Core Instructions (`GEMINI.md`):** Outlines boundaries, filing rules, and conventions the agent must respect.
* **Study Partner Mode:**
  * **Grounded Mode:** The agent queries the SQLite database and `vault_summary.json` first, referencing existing concepts to explain new ideas in the context of the vault.
  * **Freeform Mode:** A casual learning chat where the agent answers from general knowledge, transitioning to Grounded mode only if saving new notes.
* **Quality Bar (`Depth Standard.md`):** Ensures that agent-generated readings contain thorough explanations, comparisons, and structural details instead of brief bullet-point summaries.

To leverage the full power of this vault, the following Obsidian plugins are recommended:
1. **Dataview:** Used to run live queries and populate dashboards (e.g., listing the promotion queue or orphan pages). See [Dataview Queries](file:///mnt/data/life-hub/10_Knowledge_OS/99 Configs/Dataview_Queries.md) for examples.
2. **Templater:** Automates the creation of folder-specific notes using templates located in `99 Configs/Templates/`.
